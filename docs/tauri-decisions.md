# 走 Tauri 路线的几处决定

手上只有 v2.0（GPUI）文档，**v1.0（Tauri）原文缺失**。以下决定是从 v2.0 对 v1.0 的描述
（§3.1 对比表、§8–§11「基本延续」、§12–§14、附录 A）重建的，外加我自己补的取舍。

**每一条都可能与 v1.0 原文不符，拿到原文后要逐条核。**

---

## 版本与形态

- **Tauri 2**，不是 Tauri 1.x。依据是 §3.1 对比表写的是「Tauri 2 + WebView2」。
- 前端 **零依赖**：没有打包器、没有框架、没有 `node_modules`。
  依据是附录 A 把「HTML/CSS/JS 界面」列为 v1.0 的现状，v2.0 才要重写成 GPUI。

## 前端与原型的三处结构性差异

### ① 没有一个 `onclick`

原型满屏内联事件处理器。CSP 设成 `script-src 'self'`（不含 `unsafe-inline`）后它们
全部失效，改成 `data-act` + 事件委托。

这不是洁癖：正文是用户可控的 Markdown，渲染结果直接进 `innerHTML`。放开
`unsafe-inline` 等于把 XSS 的主要防线拆掉。

### ② `withGlobalTauri: true`

零依赖就意味着没有打包器，`import { invoke } from '@tauri-apps/api'` 这种裸模块
说明符在浏览器里解析不了。所以走 `window.__TAURI__` 全局。

代价写在明处：真出了 XSS，攻击者能直接调 IPC。挡这一层的是 CSP 与 capabilities
清单——能调的命令就那几条，且都不接受任意路径。
**若以后引入打包器，应当把它改回 `false`。**

### ③ 渲染时的转义顺序

`esc()` 必须在最前面：先把整段转义，再往里插我们自己生成的标签。
捕获组因此**已经是转义过的**，不能再 `esc()` 一次——那会让含 `&` 的标签显示成 `&amp;`。

原型里的 `inline()` 就有这个双重转义，移植时修掉了。

## 相对 GPUI 方案，这条路省掉的

| 省掉 | 原本的代价 |
|---|---|
| 中文输入法 | v2.0 §6 的「头号风险」，5 天 P0 验证 + 可能否决整个选型 |
| 富文本编辑器 | §3.3 ③ 估的 3–4 周 |
| 中文排版（避头尾、盘古之白、断行） | §5.5 要自己写，浏览器全包 |
| 无障碍 | §3.3 ④ 说 GPUI「基本没有」，WebView 白送 |
| 字体系统 | woff2 直接用，不必转 OTF，安装包小一半 |

## 相对 GPUI 方案，这条路多出来的

| 多出来 | 应对 |
|---|---|
| IPC 边界 | 聚合一律在 Rust 侧做完再过来；`api.js` 是唯一出入口 |
| CSP / XSS | 见上三条 |
| WebView2 运行时 | 安装器要处理 Bootstrapper 与运行时缺失检测（阶段五） |
| 图片明文落盘 | 需要 `asset:` 协议或自定义协议把解密字节喂给 WebView，不能写临时文件（阶段四） |
| 渲染一致性随 Edge 漂移 | 用到的 CSS 特性要挑保守的；`color-mix()` 需 Chromium 111+ |

## 待核对的

- v1.0 是否也用 `withGlobalTauri`，还是带打包器（Vite）。
- v1.0 的 IPC 命令签名。我按 §10.6 的 `Store` 接口反推，但 v1.0 里它们是
  `#[tauri::command]`，参数与返回类型的具体形状未知。
- 字体是内嵌 woff2（§5.7 说 v1.0 约 14MB）还是走系统字体栈。
- 原型里的 `window.storage` 是 v1.0 已有的 IPC，还是纯前端占位。
